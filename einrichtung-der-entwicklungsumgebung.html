    2. Einrichtung der Entwicklungsumgebung

    2.1. Werkzeuge installieren

    1. Node.js: Laden Sie Version 24 (LTS) von nodejs.org herunter und installieren Sie sie. [Angular CLI] 22 erfordert [Node.js] 22.22.3 (oder eine neuere Version 22), 24.15 oder höher oder 26 und später: Mit einer älteren Version lässt sich der Befehl [ng] nicht ausführen. Das Installationsprogramm installiert außerdem [npm], den Paketmanager von [Node.js]. Überprüfen Sie die Installation in einem Terminal:
    1
2
    node --version
npm --version

    1. Visual Studio Code ([VS Code]): kostenlos herunterladbar unter code.visualstudio.com. Installieren Sie die Erweiterungen [Angular Language Service] (Autovervollständigung und Validierung in [HTML]-Templates) und [Ionic] (Befehle für [Ionic] und [Capacitor] im Editor). Die Unterstützung für [TypeScript] ist bereits in [VS Code] integriert.

    2. Chrome: der Browser, mit dem die Anwendung entwickelt wird (google.com/chrome). Seine Entwicklerwerkzeuge (F12) zeigen die Anwendung in Smartphone-Größe an und erlauben es außerdem, die auf dem Smartphone installierte Anwendung zu debuggen (siehe Anhänge).

    3. MySQL 8 (oder MariaDB): nur für den JSON-Server erforderlich. Installieren Sie es zum Beispiel über Laragon (unter [Windows]), XAMPP, oder direkt über MySQL Community Server. Ein grafisches Administrationswerkzeug ([HeidiSQL], [phpMyAdmin], [MySQL Workbench], [DBeaver] ...) erleichtert das weitere Vorgehen. Dieser Kurs verwendet [Laragon].

    2.2. Installation des Ionic-Clients

    Bei [Flutter] mussten Sie ein SDK installieren: das Framework, die Sprache [Dart] und ihre Werkzeuge, die allen Projekten gemeinsam sind. Bei [Ionic] gibt es kein SDK zu installieren: [Angular], [Ionic], [Capacitor], der [TypeScript]-Compiler und ihre Kommandozeilenwerkzeuge ([ng], [cap]) sind einfache [npm]-Pakete, die in der Datei [package.json] jedes Projekts deklariert und in dessen Ordner [node_modules/] installiert werden. Jedes Projekt hat somit seine eigenen Versionen, und zwei Projekte können unterschiedliche Versionen von [Angular] verwenden, ohne sich gegenseitig zu stören.

    Den [Ionic]-Client eines Projekts zu installieren bedeutet also, seine Pakete zu installieren. Öffnen Sie in [VS Code] den Projektordner (Menü Datei / Ordner öffnen, zum Beispiel den Ordner [examples_ionic]), öffnen Sie dann eine Konsole (Menü Terminal / Neues Terminal) und geben Sie ein:

    1
    npm install

    Dieser Befehl lädt die in [package.json] beschriebenen Pakete (samt ihren Abhängigkeiten – mehrere Hundert Pakete mit insgesamt einigen Hundert Megabyte) in den exakt in [package-lock.json] aufgeführten Versionen herunter. Sie müssen diesen Befehl nur dann erneut ausführen, wenn Sie ein Paket hinzufügen oder eine Version ändern.

    Die Werkzeuge des Projekts werden dann über [npx] gestartet, das den Befehl eines im Projekt installierten Pakets ausführt (ohne [npx] würde die Konsole nach einem systemweit installierten Befehl suchen). Der Befehl [npx ng version] überprüft die Installation von [Angular]:

    1
    npx ng version

    Das Ergebnis sieht in etwa so aus (hier unter [Linux]; unter [Windows] zeigt die Zeile [Operating System] den Wert [win32 x64] an):

    [Capacitor] vergleicht die im Projekt installierten Versionen mit den zuletzt veröffentlichten Versionen. Das Paket [@capacitor/ios] ist nicht installiert: Dieser Kurs konzentriert sich ausschließlich auf [Android] (eine [iOS] -Anwendung wird auf einem [Mac] mit [Xcode] gebaut). Sobald das [Android]-Projekt erstellt wurde ([npx cap add android], siehe Beispiel 01), prüft der Befehl auch dieses Projekt.

    Nun muss die Anwendung nur noch in derselben Konsole gestartet werden:

    1
    npm start

    Öffnen Sie dann die Adresse [http://localhost:8100] in [Chrome]: Dort sehen Sie das Menü der 25 Beispiele (siehe Beispiel 01). Anders als bei [Flutter] muss kein Gerät ausgewählt werden: Im Browser wird die Anwendung von [ng serve] bereitgestellt; unter [Android] wird sie von [Capacitor] gebaut und anschließend installiert.

    Das Werkzeug [@ionic/cli] (optional). Das [Ionic]-Team veröffentlicht außerdem ein Kommandozeilenwerkzeug, das systemweit installiert wird:

    1
2
3
4
    npm install -g @ionic/cli
ionic start
ionic serve
ionic capacitor run android -l --external
    • Zeile 1: Installiert den Befehl [ionic];
    • Zeile 2: erstellt anhand einer Vorlage ([blank]: eine leere Seite, [tabs]: Tabs, [sidemenu]: ein Seitenmenü) ein neues Projekt [Ionic] + [Angular] + [Capacitor] und stellt dabei einige Fragen;
    • Zeile 3: startet den Entwicklungsserver (der seinerseits [ng serve] aufruft);
    • Zeile 4: baut die Anwendung, installiert sie auf einem Gerät ([Android]), und lädt sie bei jeder Codeänderung neu ([-l], „Live-Reload“); [--external] bewirkt, dass der Entwicklungsserver auf der Adresse des Computers im lokalen Netzwerk lauscht, die das Smartphone erreichen kann.

    Dies ist lediglich eine Komfortfunktion: [ionic] verkettet einfach die Befehle [ng] und [cap] und benötigt im Projekt eine Datei [ionic.config.json] (die von [ionic start] erstellt wird, oder von [ionic init] bei einem bestehenden Projekt). Die Projekte dieses Kurses haben keine solche Datei: Sie wurden mit [ng new] erstellt (siehe Beispiel 01), und wir verwenden direkt [ng] und [cap] , die Teil des Projekts sind. Das ist der direkteste Weg, um zu sehen, was geschieht, und er hängt von keinem auf dem Computer installierten Werkzeug ab.

    Wir beschreiben nun, wie Sie die Werkzeuge für die Entwicklung unter [Android] installieren.

    2.3. Android Studio und die Android-Kommandozeilenwerkzeuge

    Das Zielgerät dieses Kurses ist ein [Android]-Smartphone. Um die [Android]-Anwendung zu bauen und auf diesem Smartphone zu installieren, benötigt [Capacitor] das SDK [Android], und das JDK (den [Java]-Compiler, den das Build-Werkzeug [Gradle] verwendet), die zusammen mit [Android Studio], der Entwicklungsumgebung von [Google], installiert werden. [Android Studio] wird nicht zum Schreiben von Code verwendet (der Editor bleibt [VS Code]): Es dient hier dazu, das SDK [Android] zu installieren und zu aktualisieren, Emulatoren zu erstellen und gelegentlich das von [Android] erzeugte Projekt [Capacitor] zu öffnen ([npx cap open android]).

    1. [Android Studio]: Laden Sie es kostenlos von developer.android.com/studio herunter und installieren Sie es. Beim ersten Start bietet der Assistent eine Standardinstallation an: Akzeptieren Sie sie, dann lädt er das SDK [Android] herunter.

    2. Öffnen Sie den [SDK Manager] von [Android Studio] (über das Menü [Tools / SDK Manager], wenn ein Projekt geöffnet ist, oder über [More Actions / SDK Manager] auf dem Startbildschirm): Er installiert und aktualisiert die Komponenten des SDK [Android].

    3. [SDK Platforms]-Tab: Prüfen Sie, ob eine aktuelle [Android]-Plattform installiert ist. [Capacitor] 8 kompiliert Anwendungen für API 36 ([Android] 16);

    4. [SDK Tools]-Tab: Aktivieren Sie [Android SDK Build-Tools], [Android SDK Platform-Tools] (das [adb] enthält, das Werkzeug, das den Computer mit dem Gerät verbindet), [Android Emulator] (wenn Sie auf einem Emulator testen möchten) und [Android SDK Command-line Tools (latest)] (das das Werkzeug [sdkmanager] enthält) und klicken Sie dann auf [Apply].

    5. Akzeptieren Sie die Lizenzen für das SDK [Android]: [Android Studio] akzeptiert sie bei jeder Installation einer Komponente automatisch. Falls der Build der Anwendung später wegen einer nicht akzeptierten Lizenz fehlschlägt, akzeptieren Sie alle mit dem Werkzeug [sdkmanager] aus dem Paket [Android SDK Command-line Tools], indem Sie jede Frage mit [y] beantworten, bis die Meldung „All SDK package licenses accepted.“ erscheint (unter [Windows] in [PowerShell]):

    1
    & "$env:LOCALAPPDATA\Android\Sdk\cmdline-tools\latest\bin\sdkmanager.bat" --licenses

    1. JDK: [Capacitor] 8 erfordert JDK 21 oder höher. Es ist nicht nötig, eines zu installieren: [Android Studio] bringt ein eigenes mit, [JBR] („JetBrains Runtime“), das in seinem Unterordner [jbr] liegt. In neueren Versionen von [Android Studio] ist es ein [Java] 25: Das erfordert eine kleine Anpassung des von [Android] erzeugten Projekts [Capacitor] (Upgrade auf [Gradle] 9.1), wie in Beispiel 01 gezeigt.

    2. Umgebungsvariablen. [Capacitor] ([npx cap run android]) startet selbst den Build mit [Gradle] und das Werkzeug [adb]; es muss wissen, wo sich das SDK und das JDK befinden. Legen Sie unter [Windows] unter Einstellungen / System / Info / Erweiterte Systemeinstellungen / Umgebungsvariablen zwei Benutzervariablen an:

    3. [ANDROID_HOME]: der Ordner des SDK [Android]; standardmäßig [C:\Users\<name>\AppData\Local\Android\Sdk] (der [SDK Manager] zeigt ihn oben in seinem Fenster an, [Android SDK Location]);

    4. [JAVA_HOME]: der Ordner des JDK von [Android Studio]; standardmäßig [C:\Program Files\Android\Android Studio\jbr].

    Fügen Sie außerdem den Ordner [%ANDROID_HOME%\platform-tools] zur Variablen [Path] hinzu, damit Sie [adb] in einer Konsole eingeben können. Wenn [Android Studio] nicht am Standardort installiert ist, erfordert der Befehl [npx cap open android] außerdem die Variable [CAPACITOR_ANDROID_STUDIO_PATH]: den Pfad zum Programm [studio64.exe]. Die neuen Variablen sind nur für Konsolen sichtbar, die nach ihrer Erstellung geöffnet wurden; Sie müssen [VS Code] neu starten. Prüfen Sie in einer neuen Konsole:

    1
2
    adb version
& "$env:JAVA_HOME\bin\java" -version

    2.4. Einen Android-Emulator einrichten

    Wenn Sie kein Smartphone haben, können Sie die App auf einem [Android]-Emulator testen: einem virtuellen Smartphone, das in einem Fenster auf Ihrem Computer läuft. [Android Studio] installiert das Programm [Android Emulator] (sofern es im [SDK Manager] aktiviert war, siehe oben), stellt aber kein gebrauchsfertiges virtuelles Gerät bereit: Sie müssen eines erstellen.

    • [Prerequisites]: Im [BIOS] des Computers muss die Virtualisierung aktiviert sein, und unter [Windows] muss das Feature [Windows Hypervisor Platform] aktiviert sein ([Control Panel / Programs / Turn Windows features on or off]), was einen Neustart erfordert. Andernfalls startet der Emulator nicht oder bleibt sehr langsam;
    • Öffnen Sie den [Device Manager] von [Android Studio]: [More Actions / Virtual Device Manager] auf dem Startbildschirm oder [Tools / Device Manager] , wenn ein Projekt geöffnet ist (je nach Version: [View / Tool Windows / Device Manager]);
    • klicken Sie auf [Create Device], wählen Sie eine Vorlage aus (zum Beispiel [Pixel 8]) und dann [Next]. Wählen Sie ein aktuelles System-Image, [Android], für den Prozessor [x86_64] und laden Sie es über den daneben stehenden Link [Download] herunter, dann [Next] und [Finish];
    • starten Sie den Emulator über die Schaltfläche [Play] im [Device Manager];
    • warten Sie, bis der Willkommensbildschirm von [Android] im Emulatorfenster erscheint: Der erste Start kann mehrere Minuten dauern.

    Überprüfen Sie als Nächstes, ob der Computer den Emulator erkennt. Dafür gibt es zwei Befehle:

    1
2
    adb devices
npx cap run android --list
    • Zeile 1: [adb] listet die mit dem Computer verbundenen Geräte auf, eines pro Zeile: ihre Kennung (zum Beispiel [emulator-5554] für den ersten Emulator), gefolgt von ihrem Status, der [device] lauten sollte;
    • Zeile 2: Im Ordner eines [Capacitor]-Projekts (zum Beispiel [examples_ionic]) [Capacitor] listet die Geräte auf, auf denen es die Anwendung installieren kann: angeschlossene und laufende Geräte sowie in [Android Studio] erstellte Emulatoren, auch wenn sie ausgeschaltet sind (es kann sie starten). Dies ist das Gegenstück zu [flutter devices].

    [Note]: Wenn [adb devices] den Emulator mit dem Status [offline] anzeigt, hat der Emulator den Startvorgang nicht abgeschlossen, oder [adb] befindet sich in einem inkonsistenten Zustand. Versuchen Sie der Reihe nach Folgendes: (1) Warten Sie, bis der Willkommensbildschirm erscheint, und führen Sie den Befehl dann erneut aus; (2) starten Sie [adb] mit den folgenden drei Befehlen neu (unter [Windows] in [PowerShell]); der letzte sollte [device] und nicht [offline] anzeigen; (3) wählen Sie im [Device Manager] im Menü [Cold Boot Now] des Geräts [⋮] aus, oder als letzten Ausweg [Wipe Data] .

    1
2
3
    & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" kill-server
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" start-server
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices

    Wenn das Problem weiterhin besteht, prüfen Sie mit [where.exe adb], dass sich kein anderes [adb] in einer anderen Version im [Path] befindet: Zwei Versionen von [adb] , die um die Verbindung konkurrieren, verursachen dieses Problem.

    Sobald der Emulator erkannt wird, installiert sich die Anwendung mit dem folgenden Befehl auf ihm und startet. Der Befehl wird im Projektordner ausgeführt, nach [npx ng build] und [npx cap sync android] (siehe Beispiel 01); [--target] bezeichnet das Gerät anhand seiner Kennung; andernfalls fordert der Befehl Sie auf, eines auszuwählen:

    1
    npx cap run android --target emulator-5554

    Im Emulator hat der Computer, auf dem er läuft, die Adresse [10.0.2.2]: Dort sucht die Anwendung den JSON-Server (siehe Beispiel 22).

    2.5. Das Android-Smartphone vorbereiten

    Um die App auf einem echten Smartphone mit [Android] auszuführen, muss das Smartphone so eingerichtet werden, dass es vom Computer aus gesteuert werden kann:

    • Aktivieren Sie die Entwickleroptionen: Öffnen Sie [Settings / About phone], und tippen Sie dann mehrmals (meist 7-mal) auf [Build number], bis das Smartphone anzeigt, dass Sie Entwickler sind. Die genauen Bezeichnungen variieren je nach Hersteller;
    • aktivieren Sie [USB debugging] in den [Developer options] (dem im vorherigen Schritt hinzugefügten Menü);
    • Verbinden Sie das Smartphone mit einem USB-Kabel, das Daten überträgt (und nicht nur das Smartphone lädt), mit dem Computer und akzeptieren Sie auf dem Smartphone die Anfrage zur Autorisierung des USB-Debuggings. Wenn das Smartphone unter [Windows] nicht erkannt wird, installieren Sie den USB-Treiber des Herstellers („OEM USB drivers“, siehe developer.android.com/studio/run/oem-usb);
    • prüfen Sie, ob der Computer das Smartphone erkennt: Es sollte mit dem Status [device] in der von [adb devices] angezeigten Liste erscheinen (der Status [unauthorized] bedeutet, dass die Autorisierungsanfrage auf dem Smartphone nicht akzeptiert wurde) sowie in der von [npx cap run android --list] angezeigten Liste.

    Das Smartphone greift auf den Server [NestJS] über die IP-Adresse des Computers im lokalen Netzwerk zu (und nicht über [localhost], das aus Sicht des Smartphones das Smartphone selbst ist): Diese Konfiguration wird in Beispiel 22 und im Kapitel „Bereitstellung“ beschrieben.
