    9. Kommunikation mit dem Server

    Der JSON-Server von [RdvMedecins] muss nun gestartet werden (Port 8080), wie im vorigen Kapitel erklärt, vorzugsweise im CAPTCHA-Testmodus ([CAPTCHA_TEST=test]), der es erlaubt, auf jedes Bild mit „test“ zu antworten.

    Die Beispiele 22 bis 25 teilen sich einige Dateien im Ordner [src/app/common/] des Projekts: die Serveradresse ([config.ts]), die Antworttypen ([types.ts]), die Fehlerklassen ([api-error.ts]), den Anfrage-Service ([api.ts]) und eine Anmeldeleiste ([login-bar.ts]). Sie werden im Laufe der Beispiele vorgestellt, sobald sie relevant werden.

    9.1. Beispiel 22: Eine erste HTTP-Anfrage

    9.1.1. Wo ist der Server?

    Bei einem Web-Client, der vom Server selbst ausgeliefert wird, stellt sich die Frage nicht: Die Anfragen gehen mit einer relativen Adresse ([/api/captcha]) an denselben Ursprung wie die Seite. Eine auf einem Telefon installierte App hat keinen verwendbaren Ursprung: Ihre Seite wird von [Capacitor] selbst ausgeliefert, von https://localhost. Sie müssen die vollständige Serveradresse angeben, und diese Adresse hängt davon ab, wo die App läuft:

    // =========================================================================
// src/app/common/config.ts - WO liegt der JSON-Server?
// -------------------------------------------------------------------------
// Die Frage stellt sich nicht für eine Webanwendung, die vom
// Server selbst ausgeliefert wird: Die Anfragen gehen an denselben Ursprung wie die Seite
// (eine relative Adresse, /api/...). Eine MOBILE Anwendung hat aber keinen
// verwendbaren Ursprung (unter Android wird die Seite von Capacitor
// über https://localhost ausgeliefert): Ihr muss die vollständige Adresse des Servers mitgegeben werden.
//   - In der Webentwicklung (ng serve) leitet der Entwicklungsserver
//     von Angular die /api-Anfragen an den JSON-Server weiter (Datei
//     proxy.conf.json): Eine relative Adresse genügt;
//   - der Android-Emulator sieht den Rechner, auf dem er läuft, unter
//     der Adresse 10.0.2.2 (localhost ist für ihn der Emulator selbst);
//   - ein echtes Telefon, das mit demselben WLAN wie der Rechner verbunden ist, muss
//     die Adresse des Rechners in diesem Netz verwenden (192.168.1.20 ...):
//     Sie wird beim Erstellen der Anwendung angegeben:
//         ng build --define "SERVER='http://192.168.1.20:8080'"
//     oder aber wir ändern die Konstante androidServer weiter unten.
// =========================================================================

import { Capacitor } from '@capacitor/core';

// die Adresse des Servers für die Android-Anwendung, wenn nichts anderes
// vorgegeben ist: die des Rechners, vom Emulator aus gesehen
const androidServer = 'http://10.0.2.2:8080';

// der Wert, der beim Build mit --define "SERVER='...'" angegeben wird
// (ng build, ng serve). Die Option ersetzt im kompilierten Code das Wort
// SERVER durch den angegebenen Wert. Ohne sie existiert SERVER nicht: typeof
// erlaubt es uns, dies ohne Fehler zu prüfen
declare const SERVER: string | undefined;
const forcedServer = typeof SERVER === 'string' ? SERVER : '';

export const config = {
  // Capacitor.isNativePlatform(): true in der Android-Anwendung (oder iOS),
  // false in einem Browser; Capacitor.getPlatform(): 'android', 'ios' oder 'web'
  serverUrl:
    forcedServer !== ''
      ? forcedServer
      : !Capacitor.isNativePlatform()
        ? '' // das Web: derselbe Ursprung, relative Adressen
        : Capacitor.getPlatform() === 'android'
          ? androidServer
          : 'http://localhost:8080',
};
    • Zeile 21: [Capacitor], das Objekt aus [@capacitor/core] , das Informationen über die Plattform liefert, auf der die Anwendung läuft. Es kann überall verwendet werden, auch in einem Browser;
    • Zeile 25: Die Standardadresse ist die von [Android]. Der Emulator ist eine eigenständige Maschine mit eigenem Netzwerk: Für den Emulator verweist [localhost] auf den Emulator selbst. Die Spezialadresse [10.0.2.2] verweist auf den Computer, auf dem er läuft;
    • Zeilen 31–32: eine Adresse, die beim Build der Anwendung durch die Option [--define] von [Angular] vorgegeben wird: [ng build --define "SERVER='http://192.168.1.20:8080'"]. Die Kompilierung ersetzt den Bezeichner [SERVER] im Code durch den angegebenen Wert (eine Zeichenkette, daher die Apostrophe). Ohne diese Option existiert [SERVER] nicht: [declare const] teilt dem [TypeScript]-Compiler mit, dass [SERVER] ein Bezeichner ist, dessen Deklaration er nicht sieht, und [typeof SERVER] erlaubt es, seine Existenz ohne Fehler zu prüfen. Das ist das exakte Gegenstück zu [--dart-define] und [String.fromEnvironment] in [Flutter];
    • Zeilen 34–45: andernfalls eine plattformspezifische Adresse. [Capacitor.isNativePlatform()] ist in der Anwendung für [Android] (oder [iOS]) wahr, in einem Browser jedoch falsch; [Capacitor.getPlatform()] liefert 'android', 'ios' oder 'web':
    • im Browser (Zeile 41): eine relative URL (''), also derselbe Ursprung wie die App;
    • unter [Android] (Zeile 43): die Adresse aus Zeile 25;
    • anderswo (Zeile 44, [iOS], das dieser Kurs nicht behandelt): [localhost].

    Ein echtes Telefon, das mit demselben WLAN wie der Server-Computer verbunden ist, muss die Adresse des Computers in diesem Netzwerk verwenden (der Befehl [ipconfig] von [Windows] liefert sie): Sie können sie beim Kompilieren über [--define] übergeben oder die Konstante in Zeile 25 ändern. Die Firewall des Computers muss außerdem eingehende Verbindungen auf Port 8080 zulassen.

    // =========================================================================
// capacitor.config.ts - die Capacitor-Konfiguration
// -------------------------------------------------------------------------
// Capacitor macht aus der Webanwendung (dem von ng build erzeugten Ordner)
// eine Android-Anwendung: Es verpackt sie in ein Android-Studio-Projekt
// (Ordner android/), in dem sie von einer "WebView" angezeigt wird, der Engine
// des Chrome-Browsers des Telefons. Befehle (siehe Beispiel 01, "Ausführen"):
//     npx cap add android       (nur einmal: erzeugt den Ordner android/)
//     ng build                  (erstellt die Webanwendung)
//     npx cap sync android      (kopiert sie in das Android-Projekt)
//     npx cap run android       (startet sie auf einem Emulator oder Telefon)
// =========================================================================

import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  // die eindeutige Kennung der Anwendung auf dem Telefon (und im Play Store)
  appId: 'fr.stahe.examples',
  // der unter dem Symbol angezeigte Name
  appName: 'Ionic Examples',
  // der Ordner der kompilierten Webanwendung (ng build)
  webDir: 'dist/examples_ionic/browser',
  server: {
    // erlaubt unverschlüsselte HTTP-Anfragen (http://10.0.2.2:8080) an
    // den JSON-Server der Entwicklung (Beispiele 22 bis 25)
    cleartext: true,
  },
  plugins: {
    // CapacitorHttp: Die HTTP-Anfragen der Anwendung werden nicht mehr von
    // der WebView gestellt, sondern vom nativen Android-Code. Folgen (siehe
    // Beispiele 22 und 23): keine CORS-Prüfung (der JSON-Server muss nichts
    // erlauben), und die Cookies (das des Authentifizierungs-Tokens) werden
    // von Android gespeichert und automatisch zurückgesendet
    CapacitorHttp: {
      enabled: true,
    },
  },
};

export default config;
    • Zeilen 23–27: [server.cleartext: true]. Ab Version 9 von [Android] darf eine Anwendung nur noch über HTTPS kommunizieren. Unser Entwicklungsserver verwendet HTTP: Wir erlauben es. Der Befehl [npx cap sync android] überträgt diese Einstellung in das [Android]-Projekt (das Attribut [android:usesCleartextTraffic="true"], das dem Manifest hinzugefügt wird, das [Capacitor] mit dem Manifest der Anwendung zusammenführt). In der Produktion läge der Server unter HTTPS, und diese Einstellung würde entfallen;
    • Zeilen 28–37: das [CapacitorHttp]-Plugin. Die HTTP-Anfragen der Anwendung (die des HTTP-Clients von [Angular] ebenso wie die von [fetch]) werden nicht mehr von der WebView gesendet, sondern vom nativen Code von [Android]. Für einen Browser würden die Anwendung (https://localhost) und der Server (http://10.0.2.2:8080) zwei verschiedene Ursprünge haben: Der Browser würde vom Server eine CORS-Autorisierung verlangen, die der Server nicht erteilt, und würde sich weigern, das Token-Cookie mitzusenden. Der native Code kennt diese Regeln nicht. Der Code der App in [TypeScript] ändert sich jedoch nicht: Es ist [Capacitor], das die Anfragen umleitet.

    9.1.3. Und im Browser?

    Während der Entwicklung läuft die Anwendung im Browser des Computers: [ng serve] liefert sie auf Port 8100 aus, während der JSON-Server auf Port 8080 läuft. Wieder gibt es zwei Ursprünge, und [CapacitorHttp] arbeitet nicht innerhalb eines Browsers. Die Lösung ist ein Proxy, der in [angular.json] konfiguriert wird (Option ["proxyConfig": "proxy.conf.json"] des Targets [serve]):

    // =========================================================================
// src/app/ex22-http/ex22.page.ts - eine erste HTTP-Anfrage an den Server
// -------------------------------------------------------------------------
// Der JSON-Server von RdvMedecins muss laufen (Port 8080). Wir fordern von ihm
// ein CAPTCHA an: GET /api/captcha -> { "id": "...", "svg": "<svg ...>" }.
//
//   - HttpClient: der HTTP-Client von Angular (der gesamten Anwendung
//     durch provideHttpClient() in main.ts bereitgestellt). http.get<T>(address) liefert
//     ein Observable: Die Anfrage wird gesendet, wenn wir es ABONNIEREN (subscribe), und
//     die Antwort trifft später ein, ihr JSON-Body ist bereits dekodiert;
//   - eine Fehlerantwort (4xx, 5xx) oder das Ausbleiben einer Antwort landet
//     in der Funktion error des Abonnements;
//   - die Adresse des Servers hängt davon ab, wo die Anwendung läuft
//     (Browser, Android-Emulator, Telefon): siehe common/config.ts;
//   - drei darzustellende Zustände: wird geladen, erfolgreich, fehlerhaft;
//   - das Bild des CAPTCHA ist SVG: Ein <img>-Tag kann es anzeigen.
// =========================================================================

import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { Component, DestroyRef, inject, signal } from '@angular/core';
import {
  IonBackButton, IonButton, IonButtons, IonCard, IonCardContent, IonContent, IonHeader, IonNote, IonProgressBar,
  IonTitle, IonToolbar,
} from '@ionic/angular';
import { Subscription } from 'rxjs';
import { config } from '../common/config';
import { Captcha, captchaImage } from '../common/types';

@Component({
  selector: 'app-ex22',
  imports: [
    IonHeader, IonToolbar, IonButtons, IonBackButton, IonTitle, IonContent, IonProgressBar, IonCard, IonCardContent,
    IonButton, IonNote,
  ],
  templateUrl: './ex22.page.html',
  styles: `
    .error { --background: #ffebee; --color: #333; margin: 12px 0; }
    .image { border: 1px solid #ddd; border-radius: 6px; padding: 4px; text-align: center; }
    .image img { height: 60px; }
    .id { font-family: monospace; font-size: 11px; margin: 8px 0; }
  `,
})
export class Ex22Page {
  private readonly http = inject(HttpClient);
  readonly server = config.serverUrl || '(same origin: /api, ng serve proxy)';
  readonly captchaImage = captchaImage;

  // der Zustand des Bildschirms: Signals
  readonly captcha = signal<Captcha | null>(null);
  readonly loading = signal(true);
  readonly error = signal<string | null>(null);
  readonly requestCount = signal(0);

  // das Abonnement der laufenden Anfrage (falls vorhanden)
  private request?: Subscription;

  constructor() {
    this.load(); // die erste Anfrage, sobald die Seite erzeugt wird
    // die Seite wird zerstört (Zurück-Taste): Die laufende Anfrage wird abgebrochen
    inject(DestroyRef).onDestroy(() => this.request?.unsubscribe());
  }

  load(): void {
    // Das Abbestellen einer noch laufenden Anfrage BRICHT sie ab: Ihre Antwort,
    // nun nutzlos, wird nie verarbeitet (keine "veraltete" Antwort)
    this.request?.unsubscribe();
    this.loading.set(true);
    this.error.set(null);
    // <Captcha>: der Typ des erwarteten JSON-Body (ein Versprechen an den
    // Compiler: Zur Laufzeit wird nichts geprüft)
    this.request = this.http.get<Captcha>(`${config.serverUrl}/api/captcha`).subscribe({
      // next: Die Antwort ist eingetroffen (Code 2xx), ihr JSON-Body ist dekodiert
      next: (captcha) => {
        this.captcha.set(captcha);
        this.requestCount.update((n) => n + 1);
        this.loading.set(false);
      },
      // error: eine Fehlerantwort (4xx, 5xx) oder überhaupt keine Antwort
      // (Server gestoppt, falsche Adresse: status ist dann 0)
      error: (e: HttpErrorResponse) => {
        this.error.set(e.status === 0 ? 'no response (status 0)' : `the server responded ${e.status}`);
        this.captcha.set(null);
        this.loading.set(false);
      },
    });
  }
}

Warum den SVG-Text nicht direkt mit [[innerHTML]] in die Seite einfügen? [Angular] würde ihn ablehnen: Ein SVG kann Skripte enthalten, und [Angular] „bereinigt“ jedes auf diese Weise eingefügte HTML, indem es Tags entfernt, die es nicht als sicher erkennt, darunter [<svg>]. Wir könnten es erzwingen ([DomSanitizer.bypassSecurityTrustHtml]), aber ein Bild ist einfacher und risikofrei: Ein von [<img>] angezeigtes Bild führt nie Skripte aus. Bei [Flutter] war es das Paket [flutter_svg], das das SVG darstellte;

    9.2.1. Und das Cookie?

    Der Server speichert den JWT-Token in einem Cookie. Der [Flutter]-Client musste an dieser Stelle seinen HTTP-Client durch einen ersetzen, der den [Set-Cookie]-Header jeder Antwort liest, die Cookies verwaltet (und auf dem Gerät speichert) und sie im [Cookie]-Header jeder Anfrage zurücksendet: Eine [Flutter]-Anwendung hat keinen Browser, der das für sie erledigt.

    Eine [Ionic]-Anwendung muss dagegen nichts schreiben:

    • Im Browser des Computers speichert der Browser das Cookie und sendet es zurück, genau wie bei jeder anderen Website. Der [ng serve]-Proxy gibt der Anwendung und der API denselben Origin: Das [SameSite=Strict]-Cookie wird akzeptiert und zurückgesendet. Der Code der Anwendung kann dieses Cookie weder lesen noch schreiben ([HttpOnly]);
    • unter [Android] leitet das [CapacitorHttp]-Plugin (Beispiel 22) die Anfragen über den nativen Code. [Capacitor] richtet beim Start der Anwendung die Cookie-Verwaltung von [Android] (die der WebView) als Verwaltung für native Anfragen ein: Empfangene Cookies werden dort gespeichert und bei den folgenden Anfragen an denselben Server zurückgesendet. Sie bleiben auf dem Gerät erhalten (unseres hat eine Lebensdauer, die durch [Max-Age=7200] festgelegt ist; nur „Sitzungs“-Cookies ohne Ablaufzeit werden beim Start der App gelöscht): Sie bleiben angemeldet, wenn Sie die App schließen und wieder öffnen.

    Der Token wird also nie vom Code der App bearbeitet und liegt auch nicht im Klartext auf dem Gerät (der [Flutter]-Client hatte ihn in [shared_preferences] gespeichert).

// src/app/ex23-login/command.ts - eine AKTION, ihr Zustand, ihr Ergebnis
// -------------------------------------------------------------------------
// Eine asynchrone Aktion (Anmelden, Speichern ...) hat einen Zustand, den
// der Bildschirm anzeigen muss: LÄUFT sie (Schaltfläche deaktiviert)? Ist sie
// mit einem FEHLER beendet worden (Meldung)? Es ist das Muster "Command" der
// Architekturleitfäden (etwa dem von Flutter), auf das Wesentliche reduziert:
//
//     readonly loginCommand = new Command();
//     this.loginCommand.execute(() => this.logIn());   // startet die Aktion
//     loginCommand.running(), loginCommand.error()      // ihr Zustand
//
// Ihr Zustand besteht aus SIGNALS: Das Template, das sie liest, wird aktualisiert,
// wenn der Command startet und wenn er endet.
// =========================================================================

import { signal } from '@angular/core';

export class Command {
  private readonly _running = signal(false);
  private readonly _error = signal<unknown>(null);
  readonly running = this._running.asReadonly();
  readonly error = this._error.asReadonly();

  // führt die Aktion aus, sofern nicht bereits eine andere läuft
  async execute(action: () => Promise<void>): Promise<void> {
    if (this._running()) return; // keine doppelte Übermittlung (doppeltes Tippen auf die Schaltfläche)
    this._running.set(true);
    this._error.set(null);
    try {
      await action();
    } catch (e) {
      this._error.set(e); // der Fehler wird BEHALTEN, um angezeigt zu werden
    } finally {
      // finally: in ALLEN Fällen ausgeführt, bei Erfolg wie bei Fehler
      this._running.set(false);
    }
  }

  clearError(): void {
    this._error.set(null);
  }
}

    Eine asynchrone Aktion (anmelden, speichern usw.) hat einen Status, den der Bildschirm anzeigen muss: Läuft sie gerade (Schaltfläche deaktiviert)? Endete sie mit einem Fehler (Meldung)? Das ist das Muster „Command“ aus den Architekturleitfäden (in [Flutter] heißt es so), auf das Wesentliche reduziert. Der [React]-Kurs verwendete dafür die „Actions“ von [React] 19 ([useActionState]).

    • Zeilen 19–23: eine einfache Klasse (jeder Bildschirm erzeugt seine eigene mit [new]), deren Zustand aus zwei privaten Signalen besteht, die schreibgeschützt nach außen gegeben werden. Das Template, das [running()] oder [error()] liest, wird aktualisiert, wenn das Command startet und wenn es endet: Das ist die Rolle, die [ChangeNotifier] und [ListenableBuilder] in [Flutter] spielten;
    • Zeilen 26–38: eine Aktion ausführen: Läuft bereits eine andere Aktion, geschieht nichts (Zeile 27: verhindert doppeltes Absenden, wenn die Schaltfläche zweimal gedrückt wird); andernfalls wird das Command auf „läuft“ gesetzt; bei einer Exception wird der Fehler festgehalten, damit er angezeigt wird (Zeile 33); in jedem Fall ([finally], Zeilen 34–37) läuft das Command nicht mehr. Der Fehler hat den Typ [unknown]: In [JavaScript] kann jeder beliebige Wert geworfen werden, und [TypeScript] weiß deshalb nicht, was [catch] abfängt.

  'ERRORS.WRONG_CAPTCHA': 'The characters you typed do not match the image.',

  name: string;
  role: string;

interface Doctor {
  id: number;

  lastName: string;

export class Ex23Page {
  private readonly http = inject(HttpClient);
  readonly captchaImage = captchaImage;

  readonly user = signal<User | null>(null); // null: niemand ist angemeldet
  readonly doctors = signal<Doctor[]>([]);
  readonly captcha = signal<Captcha | null>(null);
  readonly ready = signal(false); // ist die Startprüfung abgeschlossen?
  readonly serverError = signal<string | null>(null);
  readonly loginCommand = new Command();
  // die Felder des Formulars, per [(ngModel)] gebunden
  readonly login = signal('admin');
  readonly password = signal('');
  readonly captchaAnswer = signal('');

  constructor() {
    this.checkSession();
  }

  private url(path: string): string {
    return `${config.serverUrl}/api${path}`;
  }

  // eine GET-Anfrage, deren JSON-Body wir haben wollen. Eine Antwort, die keine
  // 2xx ist (oder das Ausbleiben einer Antwort), weist das Promise mit einer HttpErrorResponse zurück
  private read<T>(path: string): Promise<T> {
    return firstValueFrom(this.http.get<T>(this.url(path)));
  }

  // ein POST: Das Body-Objekt wird als JSON gesendet (Header content-type: application/json)
  private post<T>(path: string, body: object): Promise<T> {
    return firstValueFrom(this.http.post<T>(this.url(path), body));
  }

  async loadCaptcha(): Promise<void> {
    this.captcha.set(await this.read<Captcha>('/captcha'));
    this.captchaAnswer.set('');
  }

  private async loadDoctors(): Promise<void> {
    this.doctors.set(await this.read<Doctor[]>('/doctors'));
  }

  // 1. wer ist angemeldet? 200 -> der Benutzer; 401 -> niemand
  private async checkSession(): Promise<void> {
    try {
      this.user.set(await this.read<User>('/auth/me'));
      await this.loadDoctors();
    } catch (e) {
      // instanceof: ein TYP-Test; e.status: der Statuscode (0: keine Antwort)
      if (e instanceof HttpErrorResponse && e.status === 401) {
        await this.loadCaptcha();
      } else if (e instanceof HttpErrorResponse && e.status !== 0) {
        this.serverError.set(`The server responded ${e.status}.`);
      } else {
        this.serverError.set(`Is the RdvMedecins JSON server running (${config.serverUrl || 'port 8080'})?`);
      }
    }
    this.ready.set(true);
  }

  // die Schaltfläche "Anmelden": Der Command führt die Aktion aus und speichert ihren Fehler
  submit(): void {
    this.loginCommand.execute(() => this.logIn());
  }

  // 2. die Anmeldung
  private async logIn(): Promise<void> {
    try {
      const user = await this.post<User>('/auth/login', {
        login: this.login().trim(),
        password: this.password(),
        captchaId: this.captcha()?.id,
        captcha: this.captchaAnswer(),
      });
      this.password.set('');
      this.user.set(user);
      await this.loadDoctors();
    } catch (e) {
      if (!(e instanceof HttpErrorResponse)) throw e;
      // e.error: der JSON-Body der Fehlerantwort, { statusCode, key, ... }
      const key: string = e.error?.key ?? 'ERRORS.SERVER_UNREACHABLE';
      await this.loadCaptcha(); // jedes Bild wird nur einmal verwendet
      // der Fehler, den der Command behalten wird
      throw new Error(`${e.status} - ${messages[key] ?? key}`);
    }
  }

  // die Meldung des vom Command behaltenen Fehlers
  errorMessage(): string {
    const error = this.loginCommand.error();
    return error instanceof Error ? error.message : String(error);
  }

  // 4. die Abmeldung
  async logOut(): Promise<void> {
    await this.post('/auth/logout', {});
    this.user.set(null);
    this.doctors.set([]);
    await this.loadCaptcha();
  }
}

// src/app/common/api-error.ts - EINE Klasse für alle Fehler der API
// -------------------------------------------------------------------------
// Alle Fehlerantworten des RdvMedecins-Servers haben dieselbe Form:
//   { "statusCode": 409, "key": "ERRORS.LOGIN_TAKEN", "params": {...}, "fields": {...} }
// Eine Anfrage kann aber auch ANDERS scheitern: gar keine Antwort
// (Netz ausgefallen, Server gestoppt, falsche Adresse) oder eine Antwort, die nicht
// von unserem Server stammt (eine Fehlerseite eines Proxys). Der HTTP-Client
// von Angular meldet alle diese Fehlschläge mit einer HttpErrorResponse; wir
// wandeln sie in EINE Klasse um, ApiError, die den vom Server gesendeten
// Übersetzungsschlüssel trägt (und gegebenenfalls seine Parameter und den Fehler
// jedes Felds).

import { HttpErrorResponse } from '@angular/common/http';

// ein Objekt { name: Text }
export type Texts = Record<string, string>;

// "extends Error": ein vollwertiger JavaScript-Fehler, den wir auslösen
// (throw) und abfangen (catch); message lautet "409 ERRORS.LOGIN_TAKEN"
export class ApiError extends Error {
  constructor(
    readonly statusCode: number, // 0: Der Server hat nicht geantwortet
    readonly key: string, // z. B.: 'ERRORS.LOGIN_TAKEN'
    readonly params: Texts = {},
    readonly fields: Texts = {},
  ) {
    super(`${statusCode} ${key}`);
    this.name = 'ApiError';
  }

  // eine Fehlerantwort des HTTP-Clients von Angular -> ein ApiError
  static fromResponse(response: HttpErrorResponse): ApiError {
    // Status 0: keine Antwort (Netz ausgefallen, Server gestoppt, falsche Adresse)
    if (response.status === 0) {
      return new ApiError(0, 'ERRORS.SERVER_UNREACHABLE');
    }
    // error: der Body der Antwort, bereits dekodiert, wenn es JSON ist
    const body: unknown = response.error;
    if (isObject(body) && typeof body['key'] === 'string') {
      return new ApiError(response.status, body['key'], texts(body['params']), texts(body['fields']));
    }
    // kein key: Der Proxy oder das Netz hat an seiner Stelle geantwortet
    return new ApiError(
      response.status,
      response.status >= 500 ? 'ERRORS.SERVER_UNREACHABLE' : 'ERRORS.SERVER_ERROR',
    );
  }
}

// ein "Type Guard": Liefert die Funktion true, weiß TypeScript, dass
// value ein Objekt ist, dessen Eigenschaften gelesen werden können
function isObject(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

// ein JSON-Objekt { "name": "ERRORS..." } -> Texts (sonst leer)
function texts(json: unknown): Texts {
  if (!isObject(json)) return {};
  return Object.fromEntries(Object.entries(json).map(([key, value]) => [key, String(value)]));
}

// src/app/common/api.ts - Anfragen an die API, in einer Zeile
// -------------------------------------------------------------------------
// In Beispiel 23 wiederholte jede Anfrage dieselben Schritte: Adresse des
// Servers, Präfix /api, Umwandlung des Observable in ein Promise, Lesen
// des Fehler-Bodys ... Wir fassen sie hier in einem SERVICE zusammen:

//   await this.api.post('/appointments', { day, slotId: 3 });

import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { inject, Injectable } from '@angular/core';
import { firstValueFrom } from 'rxjs';
import { config } from './config';
import { ApiError } from './api-error';

export type Method = 'GET' | 'POST' | 'PUT' | 'DELETE';

// providedIn: 'root': eine einzige Instanz für die gesamte Anwendung
@Injectable({ providedIn: 'root' })
export class Api {
  private readonly http = inject(HttpClient);

  // <T>: der Typ der erwarteten Antwort, vom Aufrufer gewählt
  async request<T>(method: Method, url: string, body?: unknown): Promise<T> {
    try {
      // http.request liefert ein Observable; firstValueFrom wandelt es in ein
      // Promise um (die Anfrage wird in diesem Moment gesendet). Ein Body-Objekt wird
      // als JSON gesendet (Header content-type: application/json, den der Server bei
      // einem POST verlangt); die JSON-Antwort wird dekodiert (null, wenn ihr Body leer ist)
      return await firstValueFrom(this.http.request<T>(method, `${config.serverUrl}/api${url}`, { body }));
    } catch (e) {
      // der HTTP-Client meldet JEDEN Fehlschlag (4xx, 5xx, keine Antwort) mit einer
      // HttpErrorResponse: Wir wandeln sie um. Der Rest (eine Anomalie) wird unverändert durchgereicht
      throw e instanceof HttpErrorResponse ? ApiError.fromResponse(e) : e;
    }
  }

  get<T>(url: string): Promise<T> {
    return this.request<T>('GET', url);
  }

  // ein POST hat immer einen JSON-Body: standardmäßig {}
  post<T>(url: string, body: unknown = {}): Promise<T> {
    return this.request<T>('POST', url, body);
  }

  put<T>(url: string, body: unknown): Promise<T> {
    return this.request<T>('PUT', url, body);
  }

  delete<T>(url: string, body?: unknown): Promise<T> {
    return this.request<T>('DELETE', url, body);
  }
}

import { computed, inject, Injectable, signal } from '@angular/core';
import { ApiError } from '../common/api-error';
import { Schedule, ScheduleSlot, timeRange, Person, User } from '../common/types';
import { RdvMedecins } from './rdvmedecins';

// ein Datum -> "2026-10-07" (der LOKALE Tag; toISOString würde den Tag in Greenwich liefern)
export function formatDay(d: Date): string {
  const twoDigits = (n: number) => String(n).padStart(2, '0');
  return `${d.getFullYear()}-${twoDigits(d.getMonth() + 1)}-${twoDigits(d.getDate())}`;
}

// morgen: der heutige Tag plus eins
function tomorrow(): Date {
  const d = new Date();
  d.setDate(d.getDate() + 1);
  return d;
}

export interface Message {
  success: boolean;
  text: string;
}

@Injectable()
export class ScheduleModel {
  private readonly rdvmedecins = inject(RdvMedecins);

  // ==== der Zustand ====
  readonly user = signal<User | null>(null);
  readonly doctors = signal<Person[]>([]);
  readonly clients = signal<Person[]>([]);
  readonly doctorId = signal<number | null>(null);
  readonly day = signal(formatDay(tomorrow()));
  readonly clientId = signal<number | null>(null);
  readonly schedule = signal<Schedule | null>(null);
  readonly loading = signal(false);
  readonly message = signal<Message | null>(null);

  private readonly cache = new Map<string, Schedule>();
  private readNumber = 0;

  // ==== berechnete Werte ====
  readonly loggedIn = computed(() => this.user() !== null);
  readonly isManager = computed(() => this.loggedIn() && this.user()?.role !== 'USER');

  // ==== die Aktionen ====
  async changeUser(u: User | null): Promise<void> {
    this.user.set(u);
    this.doctors.set([]);
    this.clients.set([]);
    this.schedule.set(null);
    this.doctorId.set(null);
    this.message.set(null);
    this.cache.clear(); // die Rechte haben sich geändert: Wir vergessen alles
    if (u === null) return;
    this.doctors.set(await this.rdvmedecins.getDoctors());
    // ein USER würde 403 erhalten
    if (this.isManager()) this.clients.set(await this.rdvmedecins.getClients());
  }

  chooseDoctor(id: number): void {
    this.doctorId.set(id);
    this.message.set(null);
    this.readSchedule();
  }

  chooseDay(day: string): void {
    this.day.set(day);
    this.message.set(null);
    this.readSchedule();
  }

  chooseClient(id: number | null): void {
    this.clientId.set(id);
  }

  book(c: ScheduleSlot): Promise<void> {
    return this.act(
      () => this.rdvmedecins.book(this.day(), c.id, this.isManager() ? this.clientId() : null),
      `Slot ${timeRange(c)} booked.`,
    );
  }

  cancel(c: ScheduleSlot): Promise<void> {
    return this.act(() => this.rdvmedecins.cancelAppointment(c.appointmentId!), `Appointment of ${timeRange(c)} cancelled.`);
  }

  // eine Aktion, dann IMMER ein erneutes Lesen des Terminkalenders: Der SERVER ist die Referenz
  private async act(action: () => Promise<void>, success: string): Promise<void> {
    try {
      await action();
      this.message.set({ success: true, text: success });
    } catch (e) {
      this.message.set({ success: false, text: e instanceof ApiError ? e.message : String(e) });
    }
    await this.readSchedule();
  }

  private async readSchedule(): Promise<void> {
    const id = this.doctorId();
    if (id === null) return;
    const key = `${id}/${this.day()}`;
    const number = ++this.readNumber;
    // zuerst der Cache (oder nichts), dann das Lesen
    this.schedule.set(this.cache.get(key) ?? null);
    this.loading.set(true);
    try {
      const read = await this.rdvmedecins.getSchedule(id, this.day());
      if (number !== this.readNumber) return; // ein neueres Lesen wurde gestartet
      this.cache.set(key, read);
      this.schedule.set(read);
    } catch (e) {
      if (number !== this.readNumber) return;
      this.schedule.set(null);
      this.message.set({ success: false, text: e instanceof ApiError ? e.message : String(e) });
    }
    this.loading.set(false);
  }
}

// Die Verwaltung der Clients (Admin-Konto). Dieses Formular führt
// ABSICHTLICH keine Validierung auf dem Telefon durch: Alles wird an den
// Server gesendet, der im Fall einer Ablehnung mit einem JSON-Fehler antwortet (von
// common/api.ts in einen ApiError umgewandelt):
//
//   400 { key: 'ERRORS.INVALID_FORM', fields: { lastName: 'ERRORS.LASTNAME_REQUIRED' } }
//   409 { key: 'ERRORS.PATIENT_ALREADY_EXISTS', fields: { firstName: ..., lastName: ... } }
//   409 { key: 'ERRORS.CONCURRENT_UPDATE' }         (optimistisches Sperren)
//
// Der Fehler JEDES Felds (ApiError.fields) wird seinem
// Formular-Control übergeben (setErrors): ion-input zeigt ihn unter dem Feld an (errorText).
// Seine Meldung ist der vom Server gesendete SCHLÜSSEL, den der Bildschirm übersetzt
// (Wörterbücher aus Beispiel 21). Das Ändern eines Felds löscht seinen Fehler.
// Probieren Sie: einen leeren Namen, einen Titel "Dr", einen Namensvetter (Alice DURAND), einen
// bereits vergebenen Login (martin), denselben Datensatz auf zwei Geräten geändert ...
// =========================================================================

import { Component, inject, signal } from '@angular/core';
import { NonNullableFormBuilder, ReactiveFormsModule } from '@angular/forms';
import {
  IonBackButton, IonButton, IonButtons, IonCard, IonCardContent, IonCardHeader, IonCardTitle, IonContent, IonHeader,
  IonIcon, IonInput, IonItem, IonLabel, IonList, IonNote, IonPopover, IonSelect, IonSelectOption, IonText, IonTitle,
  IonToolbar,
} from '@ionic/angular';
import { addIcons } from 'ionicons';
import { createOutline, languageOutline, trashOutline } from 'ionicons/icons';
import { Api } from '../common/api';
import { LoginBar } from '../common/login-bar';
import { ApiError, Texts } from '../common/api-error';
import { fullName, Person, User } from '../common/types';
import { injectConfirmation } from '../ex16-confirmation/confirmation';
import { languages, Translations } from '../ex21-i18n/translations';
import { Command } from '../ex23-login/command';

// die Felder des Formulars und eine zu übersetzende Meldung (ein Schlüssel und seine Parameter)
type Field = 'title' | 'firstName' | 'lastName' | 'login' | 'password';
interface Success {
  key: string;
  params: Texts;
}

@Component({
  selector: 'app-ex25',
  imports: [
    ReactiveFormsModule, IonHeader, IonToolbar, IonButtons, IonBackButton, IonTitle, IonButton, IonIcon, IonPopover,
    IonContent, IonList, IonItem, IonLabel, IonCard, IonCardHeader, IonCardTitle, IonCardContent, IonSelect,
    IonSelectOption, IonInput, IonText, IonNote, LoginBar,
  ],
  templateUrl: './ex25.page.html',
  // die Übersetzungen der Seite mit den Wörterbüchern ex25-fr.json und ex25-en.json
  providers: [{ provide: Translations, useFactory: () => new Translations('ex25') }],
  styles: `
    .warning { --background: #fff8e1; --color: #333; }
    .message { margin-top: 12px; }
    .status { font-size: 12px; }
  `,
})
export class Ex25Page {
  private readonly api = inject(Api);
  private readonly confirm = injectConfirmation();
  readonly tr = inject(Translations);
  readonly languages = languages;
  readonly titles = ['Mr', 'Mme', 'Melle', 'Dr']; // "Dr": Der Server wird ihn ablehnen
  readonly fullName = fullName;

  readonly user = signal<User | null>(null);
  readonly clients = signal<Person[]>([]);

  // das Formular: KEINE Validierungsregel, alles wird vom Server geprüft
  readonly form = inject(NonNullableFormBuilder).group({
    title: ['Mr'],
    firstName: [''],
    lastName: [''],
    login: [''],
    password: [''],
  });
  // null: Anlegen; sonst die ID des geänderten Clients und die mit seinem Datensatz gelesene Version
  readonly editedId = signal<number | null>(null);
  private version = 0;

  // die allgemeine Meldung des letzten Fehlers und die eines Erfolgs
  readonly pageError = signal<ApiError | null>(null);
  readonly success = signal<Success | null>(null);
  // das Senden an den Server: ein Command (Beispiel 23), der angibt, ob er läuft
  readonly sending = new Command();

  constructor() {
    addIcons({ languageOutline, createOutline, trashOutline });
    this.tr.start();
  }

  isAdmin(): boolean {
    return this.user()?.role === 'ADMIN';
  }

  private async reload(): Promise<void> {
    this.clients.set(await this.api.get<Person[]>('/clients'));
  }

  async onUserChange(u: User | null): Promise<void> {
    this.user.set(u);
    this.clients.set([]);
    if (u?.role === 'ADMIN') await this.reload();
  }

  // der vom Server zurückgegebene, übersetzte Fehler eines Felds ('': kein Fehler)
  fieldError(field: Field): string {
    const key = this.form.controls[field].errors?.['server'];
    return typeof key === 'string' ? this.tr.t(key) : '';
  }

  private clearMessages(): void {
    this.pageError.set(null);
    this.success.set(null);
  }

  newForm(): void {
    this.editedId.set(null);
    this.version = 0;
    // reset: die Startwerte und kein Fehler mehr
    this.form.reset();
    this.clearMessages();
  }

  edit(c: Person): void {
    this.editedId.set(c.id);
    // die mit dem Datensatz gelesene VERSION geht mit der Änderung zurück: Hat jemand
    // den Datensatz in der Zwischenzeit geändert, antwortet der Server mit 409 CONCURRENT_UPDATE
    this.version = c.version;
    this.form.reset({ title: c.title, firstName: c.firstName, lastName: c.lastName, login: c.login ?? '', password: '' });
    this.clearMessages();
  }

  // die Schaltfläche "Speichern"
  submit(): void {
    this.sending.execute(() => this.save());
  }

  private async save(): Promise<void> {
    this.clearMessages();
    const input = { ...this.form.getRawValue(), version: this.version };
    const id = this.editedId();
    try {
      const client =
        id === null
          ? await this.api.post<Person>('/clients', input)
          : await this.api.put<Person>(`/clients/${id}`, input);
      this.newForm(); // Formular geleert, Meldungen gelöscht ...
      // ... außer dieser
      this.success.set({
        key: id === null ? 'FORM.ADDED' : 'FORM.UPDATED',
        params: { name: `${client.firstName} ${client.lastName}`, login: client.login ?? '' },
      });
      await this.reload();
    } catch (e) {
      if (!(e instanceof ApiError)) throw e;
      this.pageError.set(e); // die allgemeine Meldung
      // der Fehler jedes Felds: Er wird seinem Control übergeben, das
      // ungültig wird (ng-invalid); markAsTouched markiert es als "berührt"
      // (ng-touched): Ionic zeigt dann seinen errorText an
      for (const [field, key] of Object.entries(e.fields)) {
        const control = this.form.get(field);
        control?.setErrors({ server: key });
        control?.markAsTouched();
      }
    }
  }

  async remove(c: Person): Promise<void> {
    const name = `${c.firstName} ${c.lastName}`;
    if (!(await this.confirm(this.tr.t('FORM.DELETE_CONFIRM', { name })))) return;
    this.clearMessages();
    try {
      await this.api.delete(`/clients/${c.id}`);
      this.success.set({ key: 'FORM.DELETED', params: { name } });
    } catch (e) {
      if (e instanceof ApiError) this.pageError.set(e);
    }
    await this.reload();
  }
}

    Ein Sprachwechsel übersetzt den gesamten Bildschirm neu, auch bereits angezeigte Fehler: Der Bildschirm speichert die vom Server gesendeten Schlüssel – nicht den Text – und übersetzt sie bei jeder Anzeige des Bildschirms. Probieren Sie auch: einen Titel „Dr“, einen bereits vergebenen Benutzernamen ([martin]), einen ungültigen Benutzernamen („Jean M“) oder denselben Datensatz, der auf zwei Geräten bearbeitet wird (oder in zwei Browser-Tabs, oder in der App und mit [curl]).

    Das Prinzip ist dasselbe wie bei allen Formularen der Fallstudie: Die Regeln liegen an nur EINER Stelle – dem Server; die App zeigt seine Antworten in der Sprache des Benutzers an. Natürlich spricht nichts dagegen, die Felder zusätzlich auf dem Smartphone zu validieren (Beispiel 08), um dem Benutzer schneller zu antworten; der Server muss jedoch alles erneut validieren, und sein Urteil ist endgültig.

    Der Vergleich der beiden Clients zeigt, wie sehr sich [Ionic] auf den Browser stützt: Der HTTP-Client liefert direkt [JavaScript]-Objekte (JSON ist die native Sprache von [JavaScript]), das Token-Cookie wird ohne eine einzige Codezeile weitergereicht, und eine Anfrage kann abgebrochen werden. Dafür validiert [TypeScript] das Format der Antworten zur Laufzeit nicht, was das Filtern von [Dart] ganz selbstverständlich leistete. Der [Angular]-Client für [RdvMedecins] (Kurs [Angular]) ist genau wie diese Beispiele geschrieben: derselbe [HttpClient], dieselben Services, dieselben reaktiven Formulare; nur die Anzeigekomponenten unterscheiden sich, mit denen von [Ionic] , die die eines [Android]-Smartphones nachahmen.
